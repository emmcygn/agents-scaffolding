LexiChunk Scaffolder v2

2 engineers, 4 weeks. Prove that legal-aware chunking measurably improves RAG retrieval — with numbers, an interactive demo, and publication-grade rigour.

Team:  2 engineers Duration:  4 weeks (~320 eng-hours) Outputs:  CLI + JSON + HTML + Streamlit Headline:  Retrieval improvement number by end of Week 3

01Philosophy: What 4 Weeks Must Deliver

With 2 engineers and 4 weeks, every hour must produce demo-visible signal. No gold-plating.

The one sentence that matters: "LexiChunk improves legal retrieval precision by X% over LangChain's default splitter, with statistical significance, across multiple embedding models." That claim — backed by reproducible numbers and a live demo — is the entire deliverable. Everything else is in service of making that sentence credible and visible.

What Changes from the 3-Month Plan

Kept

Structural + Retrieval Metrics

Both metric families ship. Structural metrics prove correctness (Week 1–2), retrieval metrics prove effectiveness (Week 2–3). This is the core value proposition.

Kept

Multi-Strategy Comparison

LexiChunk vs RCTS vs sentence-split vs fixed-size. But we drop multiple fixed-size variants — one fixed-size baseline (512 tokens) is enough.

Kept

Streamlit Dashboard

Ships in Week 3–4. Upload, compare chunks, run retrieval queries. But 2 pages instead of 4 — we merge upload+compare and retrieval+metrics.

Deferred

LegalBench-RAG

Moved to post-v1 backlog. 6,858 queries require stable infrastructure. The curated 20–25 queries against 5 fixtures give us the headline number. LegalBench-RAG is the "make it unassailable" step.

Deferred

LLM-Judge (DeepEval)

Moved to post-v1. Deterministic retrieval metrics are the primary proof. LLM-judge adds qualitative depth but is non-deterministic, costs money, and takes integration time we don't have.

Simplified

HTML Report

Streamlit IS the visual report. We still generate a standalone HTML, but it's a simpler Jinja2 template — not a separate design project. The Streamlit dashboard is the demo artifact.

What's Different from v1

  • 4 strategies, not 6 — dropped fixed-256 and fixed-1024. One fixed-size baseline (512) is sufficient for the comparison. Reduces compute and table clutter.
  • No LLM-Judge node — deferred to post-v1. The pipeline is fully deterministic.
  • No LegalBench-RAG loader — deferred. 20–25 curated queries with hand-annotated relevance are the primary evaluation set.
  • Contextual retrieval as a variant, not a separate strategy — LexiChunk runs with and without build_embedded_text(). This tests Anthropic's contextual retrieval finding directly.

09Tradeoffs for the 4-Week Scope

What we cut, what we kept, and why.

4 chunking strategies instead of 6

Scoped down

Dropped fixed-256 and fixed-1024. One fixed-size baseline (512) plus RCTS plus sentence-split gives 3 baselines. Adding more doesn't change the narrative — it just makes tables wider. Post-v1 can add more if needed.

LegalBench-RAG deferred

Deferred to post-v1
What we lose Publication-grade scale (6,858 queries). Comparability with published baselines. The "unassailable" layer of evidence.
Why it's okay 20–25 curated queries with hand-annotated relevance are higher signal per query. We control exactly which failure modes we test. The headline number ("X% improvement") comes from curated queries. LegalBench-RAG is the "make the blog post publishable" step — it can happen in Week 5–6.

LLM-Judge deferred

Deferred to post-v1
What we lose Faithfulness + answer relevancy scores. The qualitative "does the LLM give a better answer with these chunks?" dimension.
Why it's okay Deterministic retrieval metrics (P@k, MRR, NDCG) are the primary claim. LLM-judge is supplementary. It's also non-deterministic (run-to-run variance), costs money, and adds DeepEval as a dependency. Better to add it to a stable pipeline than rush it into v1.

2 Streamlit pages instead of 4

Scoped down
What we build Page 1: Upload + side-by-side chunk comparison (merged from upload + compare). Page 2: Retrieval query + results + metrics (merged from retrieval + metrics). Two pages that do everything, instead of four pages that each do one thing.
Why it's better Fewer navigation steps for demos. "Upload a contract, see chunks, ask a question, see the answer" is a 2-page flow. Metric drilldowns live on the retrieval page as expandable sections. Less code to maintain, test, and keep working.

Eng A as critical path bottleneck

Accepted risk
The risk If Eng A's chunking pipeline or embedding pipeline slips, Eng B has nothing to visualise. Eng B can build Streamlit against mock data, but integration will be rushed.
Mitigation Day 1 pairing on data models means Eng B can build against the interface contract, not the implementation. Eng A ships ChunkingPipeline by end of W1 Day 3 — if that slips by more than a day, escalate. Eng B can always work on query annotations, EXTENSIBILITY.md, and Streamlit layout in parallel.

HTML report is simple, not designed

Scoped down

The Streamlit dashboard is the primary visual artifact. The HTML report is a Jinja2 template with embedded Plotly charts — functional, not beautiful. It exists for sharing results without running Streamlit (email an HTML file, open in browser). If we have time in Week 4, Eng B polishes it. If not, it ships functional.

10Metrics We Ship

10 metrics. All deterministic. All grounded against published research.

# Metric Type Week Grounded Against
1 Clause Fragmentation Rate Structural W1 Reuter et al. (NLLP 2025): 0.59 vs 0.244 nDCG for structural vs fixed-size
2 Definition Preservation Rate Structural W1 Anthropic Contextual Retrieval: 35% failure reduction with context
3 Cross-Ref Resolution Rate Structural W1 Novel — no existing tool measures this
4 Hierarchy Depth Retained Structural W1 Ferraris et al. multi-layered retrieval
5 Precision@k (k=1,3,5,10) Retrieval W2 RAGAS Context Precision; MLEB standard
6 Recall@k (k=1,3,5,10) Retrieval W2 RAGAS Context Recall; critical for legal completeness
7 MRR Retrieval W2 Standard IR; used in LegalBench-RAG
8 NDCG@10 Retrieval W2 Primary metric in MLEB
9 DRM Rate Retrieval W2 Reuter et al.: >95% with naive chunking
10 Statistical Significance Meta W2 Paired t-test, standard for IR evaluation
